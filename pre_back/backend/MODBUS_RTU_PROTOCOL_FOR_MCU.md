# H2 FCU Modbus RTU 协议说明

本文档用于把单片机端原 CAN 通信改为 Modbus RTU。后端作为 Modbus 主站，STM32 FCU 作为从站。物理层仍使用 USB-RS485/RS485 收发器，但应用层不再使用自定义串口帧。

## 1. 后端串口参数

默认配置在 `config.py`：

| 参数 | 默认值 |
|---|---:|
| 模式 | `modbus_rtu` |
| 串口号 | `COM3` |
| 波特率 | `115200` |
| 从站地址 | `1` |
| 数据位 | 8 |
| 校验 | Even |
| 停止位 | 1 |
| 轮询间隔 | 50 ms |

若 USB-RS485 串口不是 `COM3`，修改：

```python
MODBUS_RTU_PORT = "COMx"
MODBUS_RTU_PARITY = "E"
```

`MODBUS_RTU_PARITY` 可选：`"N"` 无校验、`"E"` 偶校验、`"O"` 奇校验、`"M"` Mark、`"S"` Space。

## 2. 主从角色

后端是主站：

1. 周期性使用功能码 `0x03` 读取保持寄存器。
2. 前端下发控制命令时，使用功能码 `0x10` 写多个保持寄存器。

单片机是从站：

1. 维护寄存器表。
2. 响应后端 `0x03` 读请求。
3. 响应后端 `0x10` 写请求，并把控制寄存器内容转成原控制逻辑。

## 3. 寄存器映射

每个原 CAN 报文 8 字节 payload 映射为 4 个 16 位保持寄存器。寄存器高字节先传输，寄存器内容直接承载原 payload 字节顺序。

| 寄存器起始地址 | 数量 | 方向 | 原 CAN ID | 含义 |
|---:|---:|---|---:|---|
| `0x0000` | 4 | MCU -> 后端 | `0x18FF01F0` | 系统状态 |
| `0x0010` | 4 | MCU -> 后端 | `0x18FF02F0` | 电源数据 |
| `0x0020` | 4 | MCU -> 后端 | `0x18FF03F0` | 传感器数据 |
| `0x0030` | 4 | MCU -> 后端 | `0x18FF04F0` | IO 状态 |
| `0x0100` | 4 | 后端 -> MCU | `0x18FF10A0` | 控制命令 |

示例：系统状态 payload 为：

```text
12 02 00 00 00 00 00 00
```

单片机寄存器应填：

```text
0x0000 = 0x1202
0x0001 = 0x0000
0x0002 = 0x0000
0x0003 = 0x0000
```

## 4. 状态寄存器 Payload 定义

### `0x0000` 系统状态

| Byte | 说明 |
|---:|---|
| 0 | 心跳计数器，0-255 循环 |
| 1 | bit0-1：系统状态；bit2-3：故障等级 |
| 2-7 | 预留，填 0 |

系统状态建议：`0=关机完成`，`1=关机中`，`2=运行`，`3=急停/故障停机`。

### `0x0010` 电源数据

| Byte | 类型 | 说明 |
|---:|---|---|
| 0-1 | uint16 little-endian | 电堆电压，单位 0.01 V |
| 2-3 | uint16 little-endian | 电堆电流，单位 0.1 A |
| 4-5 | uint16 little-endian | DCF 输出电压，单位 0.01 V |
| 6-7 | uint16 little-endian | DCF 输出电流，单位 0.1 A |

注意：这里保持原后端解析器定义，所以 payload 内部仍是 little-endian；但 Modbus 寄存器传输本身是高字节在前。做法是把 payload 两两塞入寄存器，不要再按数值重新调换字节。

### `0x0020` 传感器数据

| Byte | 类型 | 说明 |
|---:|---|---|
| 0-1 | uint16 big-endian | 电堆温度，真实值 = raw * 0.1 - 40，单位 C |
| 2-3 | uint16 big-endian | 氢瓶压力，单位 0.01 MPa |
| 4-5 | uint16 big-endian | 进氢压力，单位 0.01 MPa |
| 6 | uint8 | 氢气浓度，单位 0.5 %vol |
| 7 | uint8 | 预留，填 0 |

### `0x0030` IO 状态

| Byte | 类型 | 说明 |
|---:|---|---|
| 0 | bit flags | bit0=进氢阀，bit1=排氢阀，bit3=加热器，bit4=风扇1，bit5=风扇2 |
| 1 | uint8 | 风扇1 占空比，0-100 |
| 2-3 | uint16 big-endian | DCF MOS 温度，真实值 = raw * 0.1 - 40，单位 C |
| 4-5 | uint16 big-endian | 故障码 |
| 6-7 | uint8 | 预留，填 0 |

## 5. 控制寄存器 `0x0100`

后端通过功能码 `0x10` 写 4 个保持寄存器到 `0x0100`，payload 定义如下：

| Byte | 说明 |
|---:|---|
| 0 | bit0-1：模式，`0=手动`，`1=自动`；bit2-4：命令，`0=STOP`，`1=START` |
| 1 | 手动控制标志：bit0=进氢阀，bit1=排氢阀，bit2=加热器，bit3=风扇1，bit4=风扇2 |
| 2 | 风扇1 目标占空比，0-100 |
| 3-4 | DCF 目标电压，uint16 little-endian，单位 0.1 V |
| 5-6 | DCF 目标电流，uint16 little-endian，单位 0.1 A |
| 7 | 预留 |

示例控制 payload：

```text
04 19 50 E0 01 64 00 00
```

含义：自动 START，手动标志 `0x19`，风扇 80%，DCF 目标电压 48.0 V，目标电流 10.0 A。

对应寄存器：

```text
0x0100 = 0x0419
0x0101 = 0x50E0
0x0102 = 0x0164
0x0103 = 0x0000
```

## 6. Modbus RTU 示例帧

读取系统状态 4 个寄存器：

```text
主站请求: 01 03 00 00 00 04 44 09
从站响应: 01 03 08 12 02 00 00 00 00 00 00 36 C2
```

写控制寄存器：

```text
主站请求: 01 10 01 00 00 04 08 04 19 50 E0 01 64 00 00 48 37
从站响应: 01 10 01 00 00 04 C0 36
```

## 7. STM32 侧实现建议

1. 使用 USART + RS485 收发器实现 Modbus RTU 从站。
2. 从站地址默认 `1`。
3. 支持功能码 `0x03` 和 `0x10` 即可。
4. 建立 `uint16_t holding_regs[]`，至少覆盖到 `0x0103`。
5. 周期性把现有状态 payload 写入 `0x0000/0x0010/0x0020/0x0030`。
6. 收到 `0x10` 写 `0x0100` 后，将 4 个寄存器拆回 8 字节控制 payload，再复用原控制命令解析逻辑。
7. 若使用 MAX485：发送响应前 `DE=1`，等待 USART TC 后 `DE=0` 切回接收。

CRC 使用标准 Modbus CRC16：初值 `0xFFFF`，多项式 `0xA001`，低字节先发。
